# ADR 004 · 能力范围修订:纳入记忆系统与 MCP,排除模型微调

- **状态**:已采纳(**修订 ADR 中此前的排除决策**)
- **影响**:[ARCHITECTURE.md §7.4](../ARCHITECTURE.md#74-记忆系统)、[§11.7](../ARCHITECTURE.md#117-mcp-集成)、[§22](../ARCHITECTURE.md#22-不引入的技术及触发条件)

---

## 背景

架构初版遵循"每项技术必须回答:解决什么问题、不用会怎样、如何验证有效"的原则,将**长期记忆系统**与 **MCP 协议集成**列入"不引入"清单,理由是"当前无明确需求"。

在后续的能力范围复审中,针对这两项识别出了具体且可验证的用例。本 ADR 记录这一**决策反转**及其依据。

> 记录反转而非静默修改,是为了保留决策链路的完整性:后来者能看到判断是如何随信息变化的,而不是看到一份"从来都正确"的文档。

---

## 决策一:纳入记忆系统

### 反转依据:识别出了具体用例

初版判断"投研问题多为一次性,跨会话复用价值未验证"。复审时发现这一判断遗漏了本场景的一个关键特性——**投研结论具有客观可验证的后验结果**。

由此产生三个具体用例:

| 用例 | 说明 | 可验证性 |
|---|---|---|
| **置信度校准** | 历史评级与实际表现对照,统计各置信度区间的真实正确率;若系统性高估则注入校准信息 | 校准前后的置信度可靠性可度量 |
| **优化飞轮的负样本来源** | 后验证伪的判断自动成为改进样本,无需人工标注 | 飞轮健康度指标可度量 |
| **重复研究的成本节省** | 复用近期结论与已检索证据,避免重复取数 | 记忆命中率与成本节省可度量 |

第一、二两项是**这个场景独有的价值**:多数 Agent 系统的记忆只能存储交互历史,而本系统的记忆能存储"判断—结果"对,直接产生可用于自我校准的信号。

### 范围界定

纳入的是**有明确用途与写入准则的记忆**,不是"记录所有交互":

- 四类记忆(情景/语义/程序/偏好)各有独立的写入条件
- 有衰减、冲突消解、时效过滤机制
- 上下文中记忆分区配额 ≤10%

**排除**:无准则的全量对话历史存储。无节制写入会让检索噪声上升并挤占上下文预算,使记忆系统成为负资产。

### 落地阶段

M3。优先级高于原计划,因为置信度校准回路是优化飞轮(M4)的输入之一。

## 决策二:纳入 MCP 协议集成

### 反转依据

初版判断"当前工具均为自有,无跨系统集成需求"。复审时明确了两个方向的实际用途:

**作为 MCP Server(主要用途)**

系统的数据接入能力(PIT 财务数据查询、带时点约束的检索、研究任务触发)对其他 Agent 系统同样有价值。以标准协议暴露,避免每个消费方重复实现数据接入与 PIT 约束逻辑。

关键约束:**复用同一套工具实现与权限校验**。若为外部另写一套,PIT 约束等正确性保证会出现旁路风险(详见 [ADR 001](./001-service-boundaries.md) 的 MCP 边界说明)。

**作为 MCP Client(次要用途,M5)**

工具注册表支持从外部 MCP Server 白名单加载工具,使系统可接入外部能力而无需为每个来源写适配代码。

### 安全前提

纳入 MCP Client 的前提是安全约束成立:

- 外部工具需显式白名单,不自动信任服务端声明的全部工具
- 外部工具返回内容与检索内容同等对待——**是数据,不是指令**
- 外部工具调用纳入审计与成本计量

若这些约束无法保证,则只做 Server 不做 Client。

### 落地阶段

MCP Server:M3。MCP Client:M5(可选)。

## 决策三:维持排除模型微调 / 强化学习 / 推理加速

### 维持排除的理由

复审同样审视了这一项,结论是**维持排除**,并补充了更明确的依据:

1. **当前瓶颈不在模型**。归因分析(ARCHITECTURE §12.9)显示,可预期的主要失效环节是检索质量与编排策略。在这两项达到上限前,微调模型不解决主要矛盾。
2. **投入产出比**。微调需要 GPU、标注数据、训练与评估流程,成本远高于 prompt 与编排改进,而后者在当前阶段的边际收益更高。
3. **前置条件未满足**。有效的微调依赖高质量训练数据,而训练数据应来自成熟评测体系筛选出的高分轨迹。评测体系尚在建设中。

### 引入触发条件

同时满足以下条件时重新评估:

1. 评测证明 prompt 与编排优化已达上限(连续多轮改进无显著提升)
2. 成本仍需进一步下降,且模型分层与缓存已充分利用
3. 已积累足够数量的高分轨迹作为训练数据

届时的**优先路径**是:用高分轨迹蒸馏小模型承担 Router 等轻量任务,而非微调主力模型。理由是这是既有模型分层策略的自然延伸,收益路径明确、失败成本低、可用评测体系直接验证。

## 决策原则的适用性反思

初版的排除原则本身没有问题,但暴露了一个执行上的偏差:

> **"当前无明确需求"有时意味着"尚未认真寻找用例",而非"确实没有价值"。**

修正后的做法:对每项候选技术,不仅问"现在有需求吗",还要问"**在本场景的特性下,它是否存在别处没有的独特用途**"。记忆系统的价值正是这样被识别出来的——它在通用场景中价值一般,但在有客观后验结果的场景中能形成自我校准回路。

这一反思不改变排除原则,而是补充了应用该原则时的检查步骤。

---

## 后果

**正面**
- 记忆系统与优化飞轮形成闭环,系统具备自我校准能力
- MCP Server 使能力可被复用,提升系统的集成价值
- 决策反转被显式记录,保留了完整的判断链路

**负面**
- M3 范围扩大,交付周期延长
- 记忆系统引入新的正确性风险(陈旧记忆污染判断),需靠写入准则与衰减机制控制

**缓解**
- 记忆的引入效果同样纳入评测:对比开关记忆的质量与成本差异,若无显著收益则回退
- 记忆写入准则作为配置项,可快速收紧
