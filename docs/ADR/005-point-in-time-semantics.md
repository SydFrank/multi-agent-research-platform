# ADR 005 · Point-in-Time 数据语义:双时间轴与强制 `as_of` 参数

- **状态**:已采纳
- **相关**:[ARCHITECTURE.md §9](../ARCHITECTURE.md#9-金融数据子系统point-in-time)

---

## 背景

系统需要对研究结论做历史回测,以验证评级信号的质量。回测的有效性完全取决于一件事:**在时点 T 做判断时,系统是否只使用了 T 时刻真实可知的信息**。

金融数据有一个关键特性:**信息的产生时间与可知时间不同**。财报描述的是某个报告期(如 2026 年一季度)的经营状况,但公告发布通常滞后数周至数月。若回测中用报告期时间做过滤,系统就会在报告期结束当天"看到"数周后才公布的数据——这就是 look-ahead bias。

其后果是隐蔽且严重的:回测结果会显著优于真实表现,而错误不会以异常或报错的形式暴露。

## 问题

如何在数据层保证任何查询都不会返回查询时点尚不可知的信息?

## 决策

采用**双时间轴数据模型**,并将 `as_of` 设为所有数据查询接口的**必填参数**。

### 1. 双时间轴

每条事实记录两个时间:

| 时间 | 字段 | 含义 |
|---|---|---|
| 事件时间 | `period_end` / `bar_date` | 数据描述的业务时点 |
| **可知时间** | `known_at` / `published_at` | 信息实际公开的时刻 |

所有 PIT 过滤基于**可知时间**,而非事件时间。

### 2. `as_of` 强制必填

```python
def get_fundamentals(symbol: str, metrics: list[str], as_of: datetime) -> list[Fact]:
    """返回 as_of 时点真实可知的最新修订版本。"""
```

**设计约束**:

| 约束 | 理由 |
|---|---|
| `as_of` 无默认值 | 有默认值会让遗漏传参变成静默的正确性错误 |
| 数据层不提供绕过 PIT 的查询接口 | 存在旁路就一定会被使用 |
| 回测路径与在线路径**共用同一查询函数** | 两套实现必然分叉,而分叉处就是 bug 的位置 |
| 检索层强制拼接时间过滤条件 | 不依赖调用方传参的正确性 |
| 工具层的 `as_of` 由框架注入,**不由模型填写** | 模型可能填错或被诱导填错,这是安全边界 |

### 3. 修订与幸存者偏差

| 问题 | 处理 |
|---|---|
| 财报修订 | 同一 `(symbol, metric, period_end)` 保留多个 `revision`;查询取 `known_at <= as_of` 中 revision 最大者 |
| 幸存者偏差 | `security` 表保留退市标的(`delisted_at` 非空),历史查询不排除已退市标的 |
| 代码变更 | `former_symbols` 记录更名历史,查询时做符号归一 |

## 理由

### 为什么不用应用层约定而要在数据层强制

应用层约定(如"记得传 as_of")在实践中必然失效:调用点会增加,新代码会遗漏,而遗漏不会立即暴露——回测照常运行,只是结果偏乐观。

把约束下沉到数据层,使得**违反约束成为不可能,而不是不推荐**:
- 必填参数让遗漏变成编译期/调用期错误,而非运行期的静默错误
- 不提供旁路接口,使"临时绕过一下"没有实现路径

### 为什么工具的 `as_of` 不能由模型填写

模型填写参数意味着 PIT 约束依赖模型的正确行为。这在两个方面不可接受:

1. 模型可能因为理解偏差填入错误时间
2. 提示注入可能诱导模型填入未来时间,从而泄露不应可见的信息

因此 `as_of` 由框架从图状态注入,模型无法感知也无法修改该参数。

### 为什么保留退市标的

若历史库中只保留当前仍存续的标的,回测样本会系统性偏向"活下来的",高估策略表现。保留退市记录是回测有效性的必要条件,而不是数据完整性的可选项。

## 后果

**正面**
- 回测结论具备可信基础,look-ahead bias 在数据层被结构性排除
- 在线路径与回测路径行为一致,不会出现"回测好、线上差"的实现性差异
- 数据修订历史被保留,可复现任意历史时点的信息视图

**负面**
- 所有数据查询签名更复杂,调用方必须显式提供 `as_of`
- 存储开销增加(保留修订版本与退市标的)
- 数据摄取需要准确的 `known_at`,依赖数据源提供发布时间;来源不提供时需要合理的估计策略并标记数据质量

**缓解**
- 无法确定 `known_at` 的数据标记 `quality_flag`,评测中单独统计其影响
- 提供测试用例覆盖 `as_of` 与 revision 的各种组合,防止查询逻辑回归

## 验证方式

以下测试用例必须通过:

1. 给定 `as_of` 早于某财报的 `known_at`,查询结果不包含该财报数据
2. 存在多个 revision 时,返回 `known_at <= as_of` 中版本号最大者
3. 已退市标的在其存续期内的历史查询可正常返回
4. 检索接口无论调用方是否传入时间过滤,结果均满足 `published_at <= as_of`
5. 工具调用中模型试图传入 `as_of` 时,该参数被框架覆盖而非采纳
